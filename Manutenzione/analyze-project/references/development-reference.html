Development Reference

Human-facing companion to development-rules.md. Markdown remains the AI-readable source of truth.

Rule contract

Every rule states scope, rationale, evidence, and enforcement mechanism.

CategoryPrinciple
StyleFollow configured formatter, linter, type checker, and nearby code.
TestingTest new behavior using the project's existing test level and command.
ErrorsValidate boundaries, preserve context, and make failures observable.
SecurityKeep secrets and personal data out of source and logs; validate untrusted input.
DependenciesRespect the package manager and lockfile; review changes deliberately.
ArchitectureDocument ownership and allowed dependency direction; prevent cycles.
OperationsDefine health, observability, migration, and rollback expectations from evidence.
CommitsUse the team convention when discoverable; otherwise record the decision needed.

Decision labels

  • Existing: evidenced by config, docs, history, or repeated code.
  • Recommended: proposed improvement with rationale and adoption cost.
  • Decisions needed: unresolved team choice.
